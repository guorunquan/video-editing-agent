# 灵剪 EditMate 总体目标

> 文档状态：v1.8 发布说明
> 适用阶段：v1.8 及后续产品迭代
> 最后更新：2026-08-10

## 1. 项目背景

灵剪 EditMate 是一个本地优先、自然语言驱动的视频剪辑 Agent。当前 v1.8 已支持视频理解、证据化剪辑建议、基础 FFmpeg 剪辑、自动字幕、字幕修改、固定区域水印处理、修改前确认、精确时间定位和成片管理。

项目有三个层次的出发点，优先级从高到低如下：

1. **秋招作品目标**：形成一个能体现 Agent 工程能力、产品判断和完整交付能力的代表项目，服务于 Agent 开发相关实习和校招面试。
2. **用户价值目标**：降低短视频剪辑门槛，让没有专业剪辑知识的用户也能从原始素材得到可发布的视频。
3. **商业探索目标**：在产品可用、用户需求得到验证后，通过增值能力或服务获得收入。

这三个目标并不冲突，但当前阶段必须优先保证项目主线清晰、闭环完整和技术决策可解释，避免为了功能数量过早扩张成完整专业剪辑器。

## 2. 总体目标

### 2.1 一句话目标

> 打造一个“AI 先理解并提出多套有证据的剪辑草案，用户通过轻量时间线检查和调整，确认后安全导出”的本地优先视频剪辑 Agent。

### 2.2 核心工作流

```text
上传素材
  → AI 理解画面、语音和时间结构
  → 生成多套差异化剪辑方案
  → 用户选择方案并生成可编辑草案
  → 在轻量时间线上预览、调整和确认
  → FFmpeg 确定性渲染
  → 下载、继续修改或导出其他版本
```

### 2.3 v1.8 已交付范围

v1.8 的目标是让用户能够精确检查视频时间点，并在不覆盖原素材的前提下完成当前帧确认：

- 播放器显示当前时间和总时长，支持拖动进度条和时间格式输入。
- 支持前进/后退 1 秒、逐帧前进/后退、设置入点和出点。
- 支持从当前播放位置截取帧并保存到受控的预览目录。
- 成片列表与截帧预览可以独立打开、播放、删除和管理。
- v1.8 不包含多轨剪辑器、复杂特效、多模型 Provider 或 MCP。

### 2.4 产品定位

灵剪不是“网页版 Premiere”或“完整复刻剪映”，而是一个 **AI 粗剪与人工修正协同工具**：

- AI 负责理解素材、提出方案、生成初步编辑操作并解释依据。
- 用户负责选择目标、审核修改、处理主观判断和最后微调。
- 编辑内核负责保存项目状态、校验操作、撤销重做和确定性导出。

期望帮助用户由“必须学习完整剪辑软件”转变为“描述目标、选择草案、做少量修正”。

## 3. 目标用户

### 3.1 核心用户

- 第一次或低频制作短视频、缺少剪辑知识的学生和普通创作者。
- 需要快速完成口播、教程、产品演示和 Vlog 粗剪的内容创作者。
- 希望用自然语言完成重复操作，但仍希望保留人工控制权的轻度剪辑用户。

### 3.2 后续用户

- 需要快速生成多个版本的自媒体运营人员。
- 希望通过 MCP 或 API 将视频剪辑接入 Agent 工作流的开发者。

### 3.3 当前非目标用户

- 依赖复杂调色、多机位、专业音频工程或大型素材库的影视专业团队。
- 需要云端多人协作、企业级资产管理和超大规模渲染集群的客户。

## 4. 核心价值

### 4.1 对普通用户

- 不需要先理解轨道、关键帧和复杂参数，也能得到可用草案。
- 每项剪辑建议带有时间点和画面/语音证据，避免“AI 凭感觉乱剪”。
- 修改前可以预览和确认，AI 不会在用户不知情时破坏原始素材。
- AI 结果不是一次性黑盒成片，用户可以继续手动调整。

### 4.2 对项目作品集

- 展示完整 Tool Calling Agent 循环，而不只是一次模型调用。
- 展示结构化状态、草稿审批、工具安全边界和失败降级。
- 展示多模态分析、FFmpeg 执行、Web 交互和测试评测的跨栈能力。
- 展示对“模型负责决策、程序负责确定性执行”的工程理解。

### 4.3 对未来商业化

- 通过真实使用数据验证高频场景，而不是先开发账号和支付系统。
- 可以逐步探索高级模板、批量处理、更强模型、云端渲染等增值能力。
- 保留本地优先和 BYOK（用户自备 Key）模式，降低早期服务成本。

## 5. 产品原则

1. **Agent 主线优先**：新功能必须强化“理解—计划—审核—执行—反馈”闭环。
2. **可解释**：剪辑建议要说明具体时间点、证据和预期效果。
3. **可编辑**：Agent 生成的是结构化编辑草案，而不是只能重新生成的一次性结果。
4. **人在回路中**：写文件和应用草案前必须获得明确确认。
5. **确定性执行**：LLM 不生成并执行任意 Shell；实际处理只经过白名单命令和参数校验。
6. **渐进式专业度**：先满足单轨粗剪和高频包装，再考虑复杂多轨能力。
7. **本地与隐私优先**：原始素材默认保留在本地；涉及云端模型时向用户明确说明。
8. **评测驱动**：重要 Agent 能力必须有样例集、指标和失败案例，而不是只靠现场演示。

## 6. 阶段性目标

### G1：形成面试可演示的完整闭环

- 固定视口工作台和精确时间定位。
- 至少三类视频能够生成多套差异化剪辑方案。
- 用户可选择方案、查看结构化草案、确认并导出。
- 关键流程有自动化测试和演示视频。

### G2：形成可持续扩展的编辑内核

- 使用 Project、Track、Clip、Effect、Operation 等结构描述编辑状态。
- Agent 和人工编辑共享同一套命令层。
- 支持草稿、版本、撤销、重做和重新渲染。
- FFmpeg 只作为渲染执行层，不再承担产品状态管理。

### G3：形成真实用户可使用的轻量产品

- 支持时间线微调、字幕、常用转场、缩放和竖屏导出。
- 对模型超时、额度不足、格式异常提供清楚的降级提示。
- 建立基础使用反馈和任务成功率统计。

### G4：验证开放性和商业可能

- 抽象模型 Provider，至少支持一个备用模型渠道。
- 在编辑命令稳定后提供本地 MCP 接口。
- 根据真实用户反馈决定模板增值、批处理或云渲染等商业方向。

## 7. 成功标准

### 7.1 秋招作品标准

- 面试者能在 3 分钟内看懂产品解决的问题和核心工作流。
- 能清楚讲解 Agent 循环、工具边界、项目状态、草稿审批和失败处理。
- README、架构图、演示视频、测试结果和技术取舍保持一致。
- 项目不依赖一次“恰好成功”的模型输出才能完成演示。

### 7.2 产品标准

- 新用户无需阅读完整文档即可上传、获取方案、确认并导出。
- 方案之间有明确目标差异，而不是同一建议的换句话表达。
- 所有时间段合法且不越界，导出结果与草案基本一致。
- 原始素材不被覆盖；用户可以取消、撤销或保留多个版本。

### 7.3 工程标准

- 核心编辑操作拥有单元测试和至少一条端到端测试。
- Agent 评测集覆盖口播、教程、产品演示和 Vlog 等典型素材。
- 模型、工具、项目状态和 UI 之间职责清晰。
- 日志能够定位一次任务的模型请求、工具调用、耗时和失败原因。

## 8. 明确不做

在核心闭环完成前，暂不投入以下方向：

- 完整专业多轨剪辑器。
- 账号、会员、支付和复杂运营后台。
- 云端多人实时协作。
- 大规模素材商城或特效市场。
- 对移动水印和复杂背景承诺无痕自动修复。
- 同时适配大量模型供应商。

## 9. 决策优先级

出现需求冲突时，按以下顺序决策：

1. 是否提升秋招展示中的技术深度和完整度。
2. 是否改善核心用户从素材到成片的成功率。
3. 是否能复用现有架构并控制维护成本。
4. 是否有真实用户证据支持。
5. 是否有明确、可持续的商业价值。
