# 灵剪 EditMate 需求分析

> 文档状态：v2.0 实现与后续需求基线
> 基线版本：v2.0
> 最后更新：2026-08-12
> 关联文档：[总体目标](./PRODUCT_GOALS.md)

## 1. 分析目的

本文档用于记录 v2.0 的真实交付范围、未完成项和后续需求优先级，避免以“不断新增 FFmpeg 功能”的方式无边界迭代。

需求围绕一条核心链路展开：

> 视频素材 → AI 多模态分析 → 多套剪辑方案 → 可编辑草案 → 用户审核/微调 → 确定性导出。

## 2. 当前能力与问题

### 2.1 v1.7 及之前已有能力

- Gemini Function Calling 与多轮工具调用。
- 视频探测、裁剪、删除片段、拼接、静音、变速、文字和截帧。
- 视频画面/音频分析和带时间点的剪辑建议。
- 本地 Whisper 可选转录、自动字幕和字幕批量修改。
- 固定区域水印模糊或覆盖。
- 修改前计划确认、输出文件管理和会话记录。
- FastAPI + 原生 Web 前端的本地体验站。

### 2.2 v1.8 已交付能力

- 播放器时间码：显示当前时间和总时长。
- 精确定位：拖动进度条、时间输入跳转、前进/后退 1 秒。
- 逐帧控制：上一帧/下一帧定位。
- 剪辑范围：设置入点、出点并校验时间顺序。
- 当前帧截取：通过 `/api/previews/capture` 保存到 `output/previews`。
- 媒体管理：成片列表与截帧预览独立打开和管理。

### 2.3 v2.0 已交付能力

- 视频分析结果持久化、字段校验、时间范围裁剪和无改动方案过滤。
- 用户用自然语言选择方案后创建结构化 `EditDraft`，不再只依赖模型口语上下文。
- 源分辨率真实视频预览；预览成功后才能确认最终导出。
- 不满意可返回原工作视频；刷新页面仍可恢复当前有效草案。
- 本地音乐库、内置高燃循环、上传、自动匹配、原声混音、循环/淡变和基础节拍吸附。
- 淡入淡出、交叉渐变、慢放、快速放大、闪白和轻微震动。
- 确定性路由「方案 N」「配上高燃音乐」「返回原视频」，避免模型错误宣称能力不存在。
- `tests/test_v1.py` 和 `tests/test_v2.py` 共 31 项自动化回归。

### 2.4 当前主要问题

| 编号 | 问题 | 影响 |
|---|---|---|
| P-01 | 页面随对话和媒体列表持续变长 | 播放器离开视野，工作流割裂 |
| P-02 | 依赖截帧命令定位画面 | 很难精确找到目标帧和编辑边界 |
| P-03 | 编辑直接产出新文件，没有项目时间线状态 | 难以撤销、微调、复用和组合复杂效果 |
| P-04 | 当前只有轻量 `EditDraft`，没有完整 Project/Track/Operation 模型 | 不能进行完整时间线微调、撤销和重做 |
| P-05 | 水印区域主要依赖默认位置或参数 | 不知道水印位置时体验差，自动处理不可信 |
| P-06 | 仅依赖 Gemini | 免费额度、网络和服务波动会阻断核心流程 |
| P-07 | 首批特效依赖固定规则，没有语义目标跟踪和光流补帧 | 复杂游戏镜头包装效果有限 |
| P-08 | 已有 31 项回归，但仍缺少真实素材 Agent 评测集和浏览器端到端测试 | 无法充分量化剪辑效果 |

## 3. 用户与场景

### U1：无剪辑经验的短视频新手

- 目标：把口播、教程或生活素材快速变成可发布短视频。
- 痛点：不理解时间线、关键帧和导出参数，不知道“应该怎么剪”。
- 期望：AI 给出几种容易理解的选择，并在执行前展示结果会如何变化。

### U2：有基础经验的内容创作者

- 目标：让 AI 完成去停顿、粗剪、字幕和简单包装，自己做最后调整。
- 痛点：重复操作耗时；纯聊天工具又缺少精确控制。
- 期望：既能自然语言操作，也能在时间线上精确修正。

### U3：Agent 开发者或自动化用户

- 目标：从外部 Agent 或工作流读取项目并提交剪辑草案。
- 痛点：普通剪辑软件缺少安全、结构化的机器接口。
- 期望：通过 MCP/API 使用与内置 Agent 相同的编辑命令，并保留人工审批。

## 4. 典型用户故事

1. 作为新手，我上传视频后希望看到三种不同目标的剪辑方案，以便不用自己从空白时间线开始。
2. 作为创作者，我希望点击方案中的时间段后播放器跳到对应位置，以便验证 AI 的依据。
3. 作为创作者，我希望拖动播放头、逐帧移动并设置入点/出点，以便精确裁剪。
4. 作为用户，我希望 Agent 的修改先进入草稿，以便预览、调整或取消。
5. 作为用户，我希望给片段添加淡入淡出、转场和缩放，以便获得更完整的短视频效果。
6. 作为水印处理用户，我希望直接在画面上框选区域，以便系统不必猜测位置。
7. 作为网络不稳定的用户，我希望主模型不可用时仍能进行手动编辑和本地处理。
8. 作为外部 Agent 用户，我希望通过 MCP 创建隔离编辑会话，并在界面审核后再应用。

## 5. 功能需求

优先级定义：

- **P0**：核心闭环必需，秋招展示前必须完成。
- **P1**：显著提升产品价值，核心闭环完成后实现。
- **P2**：差异化和扩展能力，有余力再实现。
- **P3**：长期设想，当前不进入排期。

### 5.1 工作台与精确时间定位

#### FR-001 固定视口工作台（P0）

- 播放器与对话区在桌面端保持同屏。
- 对话消息、成片列表和截帧列表分别在限定区域内滚动。
- 视频按原始比例完整展示，不能因页面高度变化持续放大。

验收标准：连续产生 50 条消息后，播放器仍可在无需滚回页面顶部的情况下操作。

#### FR-002 播放头与时间显示（P0）

- 显示当前时间、总时长和毫秒。
- 支持拖动进度条和点击跳转。
- 支持输入秒数或 `HH:MM:SS.mmm` 跳转。
- 播放器状态与时间控件双向同步。

#### FR-003 逐帧和入出点（P0）

- 根据视频 FPS 前进或后退一帧。
- 将当前播放位置设置为入点或出点。
- 可直接使用入出点创建裁剪草稿或截取当前帧。

验收标准：30 FPS 视频的逐帧步长约为 0.033 秒，设置的时间点不得超出视频范围。

### 5.2 结构化视频分析与多方案

#### FR-010 分析结果持久化（P0）

- 分析结果以 JSON 保存，而不是只保存格式化文本。
- 记录视频指纹、分析版本、模型、创建时间、观察证据和限制。
- 同一素材未变化时允许复用缓存，用户可主动重新分析。

#### FR-011 差异化方案生成（P0）

- 默认输出 2～3 个方案。
- 方案必须体现不同目标，例如高完播率、信息完整、故事节奏。
- 每个保留/删除片段必须引用具体画面或语音证据。
- 每个方案包含预计时长、置信度和已知限制。

验收标准：方案不仅标题不同，其片段选择、目标或包装策略至少有一项实质差异。

#### FR-012 方案校验与选择（P0）

- 后端校验时间越界、负数、非法重叠和预计时长。
- 点击证据时间点可跳转播放器。
- 用户选择方案后生成结构化编辑草案，并立即渲染真实视频预览。
- 没有剪切、效果或包装变化的全片保留方案不得展示为有效候选。

v2.0 状态：**已实现**。证据时间点的独立点击跳转仍可继续优化。

#### FR-013 剪辑策略模板库（P1）

- 按内容类型、发布目标、时长和节奏保存可维护模板。
- 模板提供规则和参数，不保存对受版权保护作品的直接复制内容。
- 第一阶段使用元数据筛选；模板规模扩大后再评估向量检索。

### 5.3 可编辑项目与草稿

#### FR-020 项目数据模型（P0）

项目至少包含：

- `Project`：画布、FPS、版本和当前草稿。
- `Asset`：源素材及元数据。
- `Track`：视频、音频、字幕或叠加层。
- `Clip`：源区间、时间线区间和基础属性。
- `Effect`：类型、时间范围和参数。
- `Operation`：可校验、可回放的编辑命令。

v2.0 状态：**部分实现**。当前 `EditDraft` 包含源素材、片段、效果、转场、音乐、预览、输出和版本号；完整 Project/Track/Operation 延期。

#### FR-021 命令层（P0）

- Agent 和人工编辑必须调用同一套命令。
- 命令执行前验证对象、时间范围和参数。
- 每次应用形成可追踪版本。
- FFmpeg 命令只能由受控渲染层生成。

#### FR-022 草稿审核（P0）

- Agent 操作先写入隔离草稿。
- 界面显示操作摘要、影响片段和来源理由。
- 用户可全部接受、全部拒绝或修改后应用。
- 草稿应用应形成一个原子撤销步骤。

v2.0 状态：**部分实现**。支持整体预览、调整配乐/特效、确认、取消和返回原视频；逐操作接受/拒绝和原子撤销延期。

#### FR-023 撤销、重做和版本（P1）

- 支持至少 20 步撤销/重做。
- 原始素材始终只读。
- 可从相同素材保存多个项目版本。

### 5.4 轻量剪辑器

#### FR-030 单轨时间线（P0）

- 显示视频片段、字幕/文字层和播放头。
- 支持选择、拖动、裁剪、分割、删除和吸附。
- 时间线变化同步到项目状态和预览。

第一阶段不要求完整专业多轨、复杂调色或多机位能力。

v2.0 状态：**延期**。当前使用播放器、时间控制和方案卡完成审核，没有可拖拽图形时间线。

#### FR-031 AI 操作可视化（P0）

- AI 新增、删除或调整的片段有明显标记。
- 用户可查看操作理由并跳转对应证据。
- 人工修改后不得被后续 Agent 无提示覆盖。

#### FR-032 画布与短视频比例（P1）

- 支持 16:9、9:16 和 1:1。
- 提供 `contain`、`cover` 和手动主体区域调整。
- 导出前明确显示裁切范围。

### 5.5 特效系统

#### FR-040 特效注册表（P1）

- 所有特效使用统一名称、参数 Schema、默认值和合法范围。
- 特效既可由 Agent 添加，也可由用户手动修改。
- 不允许模型直接生成任意 FFmpeg 滤镜字符串。

#### FR-041 首批特效（P1）

首批只实现高频、可稳定渲染的能力：

- 淡入和淡出。
- 相邻片段交叉渐变。
- 缓慢放大/缩小。
- 指定时间段局部放大。
- 横屏转竖屏的画面适配。

验收标准：预览和最终导出的开始时间、持续时间和主要视觉结果一致。

v2.0 状态：**已交付首批规则效果**，包括淡入淡出、交叉渐变、慢放、快速放大、闪白和轻微震动。局部目标自动跟踪与画布比例调整延期。

### 5.6 配乐系统

#### FR-045 本地配乐与自动匹配（P0）

- 提供可立即演示的内置免版权高燃循环，并允许上传本地音乐。
- 根据方案情绪和能量自动选择音乐，允许用户改音乐和音量。
- 音乐按成片长度循环，支持淡入淡出、保留原声混音和基础节拍吸附。
- 「给整个原视频配乐」不得先静音或要求用户去外部软件完成。

v2.0 状态：**已实现**。在线音乐搜索、版权授权与下载延期。

### 5.7 水印处理

#### FR-050 可视化区域框选（P1）

- 用户可在暂停画面上拖动和缩放矩形区域。
- 区域坐标保存为归一化值，适配不同分辨率。
- 应用前可预览模糊或覆盖结果。

#### FR-051 自动候选区域（P2）

- 从多个时间点采样画面，寻找长期稳定的文字或图形区域。
- 返回候选框、置信度和采样依据。
- 用户确认后才处理，低置信度时不得自动应用。

#### FR-052 能力边界（P0）

- 明确说明固定区域模糊/覆盖不等于无痕修复。
- 不对移动水印和复杂背景承诺自动成功。
- 产品提示仅处理用户拥有合法权利的素材。

### 5.8 模型与额度管理

#### FR-060 Provider 抽象（P1）

- 统一封装聊天、工具调用和多模态分析接口。
- 业务代码不直接依赖单一厂商 SDK 数据结构。
- 能力配置标明是否支持 Tool Calling、视频理解和 JSON 输出。

#### FR-061 备用 Provider（P1）

- Gemini 之外至少支持一个备用模型入口。
- API Key 只保存在服务端或本地配置中，不返回浏览器。
- 切换模型时明确说明能力差异。

#### FR-062 失败降级（P0）

- 对 429、超时、服务不可用和响应格式错误分类提示。
- 视频分析失败时，手动编辑和本地 FFmpeg 功能仍可使用。
- 缓存可复用的分析结果，避免重复消耗额度。

### 5.9 MCP 开放能力

#### FR-070 本地 MCP Server（P2）

- 在编辑命令层稳定后提供本地 MCP 接口。
- 内置 Agent 和 MCP 客户端共享项目读取与编辑命令。
- 默认只监听本机；非本机访问必须使用 Token。

#### FR-071 MCP 编辑会话（P2）

建议首批工具：

- `get_project`
- `analyze_video`
- `begin_edit_session`
- `add_edit_operation`
- `review_edit_session`
- `apply_edit_session`
- `discard_edit_session`
- `render_preview`

外部 Agent 只能修改隔离草稿；未审核草稿不得改变正式项目。

### 5.10 渲染与成片管理

#### FR-080 预览与最终导出（P0）

- 草稿预览保持源视频分辨率，以更快编码 preset 控制等待时间，不以模糊画质换速度。
- 没有成功预览的草稿禁止直接确认最终导出。
- 预览不会覆盖原视频或工作视频；用户可随时返回原视频。
- 最终导出显示状态、进度、耗时和失败原因。
- 导出结果关联项目版本和渲染参数。

v2.0 状态：预览门禁、源分辨率、原视频恢复和草案关联已实现；精确进度百分比仍待增强。

#### FR-081 成片版本（P1）

- 用户可以保留同一项目的多个导出结果。
- 成片可重命名、下载、设为新素材或定位文件。
- 删除仅限受控输出目录，不删除原始素材。

## 6. 非功能需求

### NFR-001 安全

- 禁止执行模型生成的任意 Shell。
- 路径访问限制在配置的素材和输出目录。
- 写操作必须经过确认或显式自动审批模式。
- API Key 和代理凭据不得进入日志、前端状态或 Git。

### NFR-002 性能与反馈

- 普通本地交互在 200 毫秒内给出可见反馈。
- 超过 1 秒的分析或渲染任务显示运行状态。
- 长任务支持查询状态；后续可增加取消能力。
- 时间线拖动和播放头更新不应触发完整视频重渲染。

### NFR-003 兼容性

- 首要支持 Windows 和现代 Chromium 浏览器。
- 输入至少支持 MP4、MOV、MKV 和 WebM。
- 对浏览器不能直接播放的编码给出转码提示。

### NFR-004 隐私

- 默认本地保存项目、素材索引、会话和成片。
- 视频发送给云端模型前向用户说明。
- 文档不得承诺未实现的完全离线能力。

### NFR-005 可观测性

- 每个任务拥有唯一 Job ID。
- 记录模型、耗时、工具名、参数摘要、状态和错误分类。
- 日志对路径、Key 和用户文本中的敏感信息做必要脱敏。

### NFR-006 测试与评测

- 编辑命令和参数校验需要单元测试。
- 渲染层需要覆盖典型 FFmpeg 集成测试。
- 关键用户链路至少有一条端到端测试。
- 建立 10～20 个样例的 Agent 评测集，覆盖口播、教程、产品演示和 Vlog。

## 7. 建议数据结构

```text
Project
├── canvas
├── assets[]
├── tracks[]
│   └── clips[]
│       ├── source_range
│       ├── timeline_range
│       └── effects[]
├── captions[]
├── analysis
├── drafts[]
├── operation_history[]
└── exports[]
```

原则：项目 JSON 是产品事实来源，FFmpeg 输出文件是项目状态的渲染结果，而不是唯一状态。

| 版本 | 目标 | 主要范围 | 建议周期 |

| v1.8 | 精确定位与工作台 | 时间显示、拖动、逐帧、入出点、当前帧截取 | 已完成 |

| v2.0 | 预览与包装闭环 | EditDraft、源分辨率预览、本地配乐、首批效果、确认导出 | 已完成 |
| v2.1 | 草案可编辑性 | 完整项目命令、时间线微调、撤销/重做、画布比例 | 待评估 |
| v2.2 | 开放与降级 | Provider 抽象、备用模型、本地 MCP | 可选 |

v2.0 已完成“分析—选方案—真实预览—调整包装—确认导出”闭环；后续围绕草案可编辑性和效果质量扩展，不直接扩张为完整专业剪辑器。

### 8.1 已确认延期项

1. 击杀播报/OCR 驱动的逐帧高光定位。
2. 目标检测与自动跟踪式放大。
3. 光流补帧级电影慢动作。
4. 在线音乐检索、版权授权和自动下载。
5. 完整多轨时间线编辑器。

## 9. 衡量指标

### 9.1 Agent 指标

- 工具选择正确率。
- 时间参数合法率。
- 方案证据覆盖率。
- 方案实质差异率。
- 用户确认前误写文件次数，目标为 0。
- 从自然语言目标到可渲染草稿的成功率。

### 9.2 产品指标

- 新用户首次成功导出率。
- 从上传到首次预览的耗时。
- 方案被选择的比例。
- Agent 草稿被直接接受、修改后接受和拒绝的比例。
- 单个成片需要的人工操作次数。

### 9.3 项目展示指标

- 3 分钟演示能否完成“上传—分析—选择—微调—导出”。
- 是否能展示一次失败降级和一次安全拦截。
- 是否有可复现的测试报告、架构图和技术取舍记录。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 功能范围扩张为完整剪辑器 | 坚持单轨和高频能力边界，未完成 P0 前不进入 P2 |
| 多模型适配工作量失控 | 先抽象接口，只接一个备用 Provider |
| AI 建议空泛或方案雷同 | 结构化输出、模板约束、后端校验和离线评测 |
| 预览与 FFmpeg 导出不一致 | 限制首批特效，并为每种效果建立对照测试 |
| 自动水印检测误判 | 候选框 + 置信度 + 用户确认，保留手动框选 |
| 模型配额或网络导致演示失败 | 缓存分析、准备离线项目样例、允许手动编辑继续运行 |
| 秋招前无法完成全部路线 | 以当前 v2.0 预览/配乐/效果闭环为可演示基线，其余能力明确延期 |

## 11. 秋招版本完成定义

达到以下条件即可将项目视为“面试可交付”，不必等待全部远期功能：

1. 新用户可以在页面中完成上传、分析、选择方案、确认和导出。
2. 至少三类样例视频能产生带证据的差异化方案。
3. 用户可以通过播放头和时间输入验证、修正剪辑边界。
4. Agent 的修改以结构化草稿展示，未经确认不会写入正式项目。
5. 至少实现淡入淡出、一个转场和一个画面缩放效果。
6. 测试覆盖安全确认、项目命令、时间校验和一条端到端主流程。
7. README、架构图、演示视频和简历描述与真实能力一致。
